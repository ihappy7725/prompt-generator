# PROMPTERA

복사해서 빈칸만 바꾸면 되는 프롬프트 모음. 여러 프롬프트를 하나로 합치거나 단계별로 이어 쓸 수 있습니다.

현재 **프롬프트 3,400개 · 카테고리 34개 · 대분류 7개 · 기법 24개**입니다. 카테고리당 100개, 모든 기법에 170개 이상의 프롬프트가 연결됩니다. 상단의 프롬프트 카테고리와 프롬프트 기법에서 각각 찾을 수 있습니다. 카테고리 메뉴 안에서 이름·상황으로 검색하거나 목록에서 대분류·카테고리·기법·난이도를 함께 선택하세요. 목록은 페이지당 36개씩 표시하고, 주소에 페이지·검색·필터를 함께 보존합니다. 검색에는 카테고리 이름도 포함되며 `/` 키로 검색창에 이동합니다.

기존 340개를 보존하고, 새 실전 상황 170개에 서로 다른 지시·입력·출력 흐름 18가지를 적용한 3,060개를 추가했습니다. 따라서 3,400개는 기법별 변형을 포함한 사용 가능한 프롬프트 수이며, 서로 다른 주제 3,400개를 뜻하지 않습니다. 역질문·롤플레이·아웃라인·단축 명령 등은 첫 결과를 바로 완성하는 대신 사용자의 다음 입력을 기다리는 대화형 템플릿입니다. 추천에서는 같은 실전 상황의 변형이 중복으로 나오지 않도록 합니다.

밝은 배경과 큰 제목, 번호 섹션, 얇은 격자로 구성했습니다. [카카오 지속가능성](https://sustainability.kakao.com/ko)의 흰색·차콜과 연노랑·하늘색 그라데이션에서 디자인 방향을 가져왔으며, 그래픽은 이 사이트의 질문·프롬프트 카드로 직접 구성했습니다. 헤더·푸터에는 `assets/logo.png`, 탭·홈 화면 아이콘에는 `assets/icon.png`를 사용합니다.
이 구성을 유지하면서 민트·살구색·연보라를 카테고리와 도구 카드에 구분해 적용하고, 히어로의 빛·기하 도형·프롬프트 카드 장식을 보강했습니다. 생성기 소개에는 작업 입력과 예시 선택을 함께 배치했습니다.

홈의 **나에게 맞는 프롬프트 찾기**에서 분야·작업 목적·선택 키워드를 입력하면 조건에 맞는 항목 중 최대 3개를 추천합니다. 분야는 지정한 대분류 안에서, 키워드는 모두 포함하는 항목으로 좁힙니다. 제목·설명·태그의 목적 관련 표현을 우선 비교하고, 쉬운 난이도와 적은 빈칸 수를 함께 고려합니다. 추천 카드에서 상세·복사·즐겨찾기·카트 담기를 바로 사용할 수 있습니다. 외부 API 호출 없이 브라우저에서 동작합니다.

홈에는 스크롤에 따른 섹션 등장, 질문 카드의 떠오름·회전, 메뉴·화면 전환, 카드·버튼 반응 모션을 적용했습니다. 장식 모션은 홈이 화면에 보일 때만 실행합니다. **모션 끄기** 선택은 브라우저에 저장되고, 기기의 **동작 줄이기** 설정이 켜지면 자동으로 모션을 끕니다. 모션이나 관찰 API가 없어도 콘텐츠와 기능은 표시됩니다.

홈 하단의 **생성기 전용 섹션**에서 작업을 입력해 이어가거나, 상단의 독립된 **생성기** 버튼을 누르세요. 생성기는 별도 화면으로 열리고 도구 메뉴에는 프레임워크 빌더·질문 다듬기·기법 사전만 표시됩니다. 홈 순서는 히어로 → 맞춤 추천 → 카테고리 → 도구 → 시작 추천 → 생성기입니다. 생성기에서 제공사·모델·본인 API 키를 연결한 뒤 **프롬프트 생성하기**를 누르면 생성 결과를 수정하고 복사할 수 있습니다. 기존 `#t=ape` 주소는 그대로 사용합니다. 고급 설정에서 비교할 후보 수와 전략을 선택할 수 있지만, 결과에는 최종 프롬프트 하나만 표시합니다. 작업 자체의 답변을 실행하는 기능과 구분합니다.

생성기 키와 생성 결과는 메모리에만 남고 localStorage에 저장하지 않습니다. 키는 선택한 제공사로 직접 전송하며, 제공사를 바꾸거나 키 지우기를 누르거나 페이지를 새로고침하면 입력한 키가 지워집니다. 입력한 작업·조건은 기존 도구 설정처럼 이 브라우저에 저장됩니다. 생성 버튼을 누를 때만 API를 호출하며 본인 계정의 사용량으로 처리됩니다. 이 방식은 서버나 **Vercel Environment Variables가 필요하지 않습니다**. 생성 취소·중복 클릭 방지·생성 실패 후 기존 결과 유지도 지원합니다.

## 영문 변환·복사

상세 프롬프트·생성 결과·조립 카트·프레임워크 빌더·질문 다듬기에서 **영문 변환·복사**를 사용할 수 있습니다. 변환 창에서 원문을 확인하고 본인 API 키로 변환한 뒤, 결과를 수정·복사하세요. 답변 언어는 한국어가 기본이며 영어 또는 원문의 언어 지시 유지로 바꿀 수 있습니다. 특정 언어로 번역하거나 예문을 만드는 작업의 대상 언어는 보존하도록 요청합니다.

영문은 항상 성능 향상을 보장하지 않습니다. 한국어가 필요한 작업은 원래 언어를 유지하고, 사용하는 모델·작업에서 영문 버전이 유용한지 비교해 보세요. [Claude 다국어 지원 문서](https://platform.claude.com/docs/en/build-with-claude/multilingual-support)는 언어와 지역 맥락을 명확히 하고 실제 사용 사례에서 평가하도록 안내합니다. [OpenAI 프롬프트 가이드](https://developers.openai.com/api/docs/guides/prompt-engineering)도 작업에 맞는 명확한 지시와 평가를 다룹니다.

변환은 원문 작업을 실행하지 않고 지시문만 번역하도록 요청합니다. 빈칸·숫자·URL·코드·단축 명령은 임시 토큰으로 보호하며, 응답에서 누락·중복·알 수 없는 토큰이 발견되면 새 결과를 표시하지 않습니다. 이 검사는 보호한 값의 보존을 확인하며 번역 의미 전체의 정확성을 보장하지는 않습니다. 원문은 수정하지 않고, 새 원문을 열면 이전 원문의 변환 결과를 비웁니다. 같은 원문을 다시 열 때는 메모리의 결과를 사용하고 자동으로 과금 요청을 반복하지 않습니다.

키·원문·변환 결과는 브라우저 저장소에 쓰지 않습니다. 생성기에 입력한 키는 현재 페이지에서 재사용할 수 있고 변환기 키 지우기를 누르면 변환기에서만 제거됩니다. 변환 버튼을 누를 때 선택한 제공사로 보내며 본인 계정의 사용료가 발생합니다. Vercel 환경변수는 추가로 필요하지 않습니다. 모의 API 테스트로 보호 값·답변 언어 선택·원문 유지·편집/복사·오류·취소를 확인했으며 실제 유료 번역 호출은 검증하지 않았습니다.

## 링크 공유 미리보기

`index.html`에 Open Graph와 X(Twitter) 카드 정보를 정적으로 설정했습니다. 공유 이름은 **PROMPTERA**, 제목은 **복사해서 바로 쓰는 프롬프트 모음 · 생성기**이며, 기존 로고가 들어간 `assets/share-card.png`(1200×630)를 사용합니다. 홈페이지 안의 디자인과 로고 파일은 바꾸지 않습니다.

기준 주소는 `https://prompt-generator-black.vercel.app/`입니다. Vercel에 변경 파일을 다시 배포하면 적용되며 환경변수는 필요하지 않습니다. 도메인을 변경할 때는 `index.html`의 canonical·og:url·og:image·twitter:image 주소와 공유 이미지 하단 주소를 함께 바꾸세요. 공유 이미지는 Windows의 `tools/build-share-image.ps1`로 다시 만들 수 있으며, 배포할 때는 이미 생성된 PNG만 제공하면 됩니다.

표시 여부와 형태는 각 공유 앱의 정책에 따라 다릅니다. [Vercel의 Open Graph 검사](https://vercel.com/docs/deployments/og-preview)로 배포 결과의 메타데이터를 확인할 수 있습니다. 기존에 공유한 링크는 앱에 저장된 미리보기 때문에 갱신이 늦을 수 있습니다.

## 프롬프트 추가하기

개수 제한은 없습니다. 카테고리 파일에 항목을 넣고 빌드하면 됩니다.

1. `data/prompts/<카테고리>.json` 의 `prompts` 배열에 아래 틀로 추가
2. `node tools/build.js` (색인과 묶음 파일 갱신)
3. `node tools/check.js` (문제가 있으면 줄 단위로 알려 줍니다)

새 카테고리를 만들 때는 `data/prompts/<새id>.json` 파일을 만들고 `category` 칸을 채우면 됩니다. 파일 이름과 `category.id`가 같아야 합니다.
`data/taxonomy.json`의 `groups`에도 새 카테고리를 정확히 한 번 넣으세요. 상단 메뉴와 홈의 대분류는 이 목록을 사용합니다.

실전 기법 확장 항목은 `tools/scale.js`의 상황 원고와 실행 지시를 수정한 뒤 `node tools/scale.js`와 빌드를 실행하세요. 이 명령은 `origin: scenario-technique-v1`인 생성 항목을 갱신하며 기존 001~010번은 보존합니다. 생성 항목을 JSON에서 직접 수정하면 다음 재생성 때 바뀔 수 있습니다. 데이터 검사는 본문 중복·기법의 실제 실행 지시·상황별 18개 변형·연결이 없는 기법도 확인합니다.

### 화면 동작 검사

임시 폴더에 DOM 검사 도구를 설치한 뒤 실행할 수 있습니다. 프로젝트 실행에는 추가 의존성이 필요하지 않습니다.

```powershell
npm.cmd install --prefix "$env:TEMP/promptera-qa" linkedom --ignore-scripts --no-audit --no-fund
node tools/check-ui.js
node tools/check-api.js
```

분야·목적·검색어 추천, 빈 추천·초기화·복사·즐겨찾기·상세 연결, 모션 끄기·설정 저장·기기 설정 변경·화면 밖 정지·스크롤 등장과 함께 기존 홈 카드, 카테고리 검색, 상세 예시·복사, 카트 병합·체인, API 패널 이동, 필터 주소 복원, 메뉴 폭 전환, 파일 직접 열기용 묶음 데이터를 검사합니다. DOM 검사는 실제 레이아웃 엔진이나 화면 재생을 사용하지 않습니다. 실제 브라우저에서 320·390·768·1280px 배치·줄바꿈·모션 재생은 별도로 확인해야 합니다.

빈칸 설명을 여러 개 한꺼번에 채울 때는 `tools/fill.js`를 씁니다. 짧은 채움 파일을 만들어 넘기면 되고, 자리 하나만 고칠 때는 `null`로 나머지를 그대로 둘 수 있습니다.

```bash
node tools/fill.js 채움파일.json
```

```json
{
  "study-006": {
    "빈칸": ["화면에 보일 이름", "무엇을 적는지", "예시 값", "textarea"],
    "다른 빈칸": [null, null, "예시만 바꾸기"]
  }
}
```

`type` 자리에 `"select|보기1|보기2"`처럼 적으면 고르는 칸이 됩니다. 예시 값은 문장이 아니라 **명사형**으로 쓰세요. 프롬프트 문장이 `{빈칸}입니다`처럼 이어지기 때문에 `~합니다`로 끝나면 어색해집니다.


### 칸 설명

| 칸 | 뜻 |
|---|---|
| `blocks` | 수업에서 배운 다섯 칸 뼈대. 역할 · 작업 · 입력 · 제약 · 출력 |
| `placeholders` | 빈칸 하나하나의 이름 · 설명 · 예시. 화면의 입력 폼이 이걸로 만들어집니다 |
| `type` | `narrative`(서술형) · `instruction`(지침형) · `function`(함수형) |
| `techniques` | `data/taxonomy.json`의 기법 id. 카드의 칩과 기법 필터에 쓰입니다 |
| `framework` | 프레임워크 id 또는 `null` |
| `blocksSource` | `manual`(손으로 다듬음) · `auto`(변환 스크립트가 만든 것) |
| `combine.produces / consumes` | 결합 추천에 쓰는 꼬리표. 앞 프롬프트의 `produces`와 뒤 프롬프트의 `consumes`가 맞으면 추천합니다 |
| `combine.order` | 작은 수가 앞 단계(기획·정리), 큰 수가 뒤 단계(검토·분석) |
| `placeholders[].type` | `text` · `textarea` · `select`(이때 `options` 필요) |

### 지킬 것

- 한국어, 쉬운 말
- `level`은 `쉬움` · `보통` · `전문` 중 하나
- 사실 · 통계 · 숫자를 지어내지 않기. 필요하면 빈칸으로 두기
- 특정 회사 · 사람 · 상품을 홍보하거나 깎아내리지 않기
- 건강 · 돈 · 법률 프롬프트에는 전문가 확인이 필요하다는 문장을 넣기 (점검 스크립트가 확인합니다)

## 결합 기능

- **병합**: 담은 프롬프트를 STEP 1, 2, 3으로 묶어 한 개의 프롬프트로 만듭니다. 같은 이름의 빈칸은 한 번만 입력하고, 조건이 부딪치면 경고를 띄웁니다.
- **체인**: 단계마다 따로 복사해서 차례로 보냅니다. 2단계부터 `{앞 단계 결과}` 자리가 생깁니다.
- **기법 토핑**: 페르소나 강화, 예시 주기, 팩트체크, 스스로 검토 등 17개를 켜면 프롬프트에 해당 문장이 더해집니다.

## AI로 바로 실행

API 키는 사용자가 화면에서 직접 넣습니다. 코드에는 키가 없습니다. 프롬프트 생성기는 키 저장 기능을 제공하지 않습니다. 기존 프롬프트 상세·카트·기타 도구의 실행 패널은 `이 브라우저에 저장`을 선택할 수 있으며, 선택한 경우에만 해당 키가 localStorage에 남습니다. 공용 컴퓨터에서는 저장하지 마세요. 모델 이름은 바뀔 수 있어서, 404 오류가 나면 각 서비스 문서에서 사용 가능한 모델 이름을 확인해 고치면 됩니다.

API 요청 형식 참고: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Claude Messages](https://platform.claude.com/docs/en/api/messages/create), [Gemini API](https://ai.google.dev/api). 기본 모델은 `gpt-4.1-mini`, `claude-sonnet-5-5`, `gemini-3.8-flash`이며 직접 변경할 수 있습니다. 모델 접근 가능 여부는 본인의 계정에 따라 다릅니다. Gemini 기본값은 신규 프로젝트에 권장되는 모델을 [공식 모델 목록](https://ai.google.dev/gemini-api/docs/models)에서 확인해 반영했습니다.

`check-ui.js`와 `check-api.js`는 가짜 키와 모의 응답만 사용합니다. 실제 유료 요청의 성공, 제공사별 계정 권한·브라우저 정책은 검증하지 않으므로 본인 키로 생성 버튼을 눌러 확인해야 합니다.
